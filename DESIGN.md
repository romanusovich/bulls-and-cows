## 1. Структуры данных и алгоритмы

### Состояние игры

Всё состояние игры лежит в одном объекте GameState (файл src/core/types.ts) со следующими полями:

- `status` - 'settings', 'playing' или 'won';
- `settings` - это длина и система;
- `secret` - само секретное слово;
- `history` - массив попыток;
- `startedAt` и `finishedAt` - время старта и победы.

Все в одном объекте чтобы было проще передавать состояние в функции, вместо тысячи переменных. Все поля помечены readonly для иммутабельности, новые объекты возвращаются через spread оператор. Секрет и попытки хранятся как строки чтобы сохранить 0 в начале.

### История попыток

История это массив объектов `GuessHistory`, чтобы сохранить порядок попыток. Добавление попытки просиходит путем создания нового массива через spread оператор. Чтобы не было повторяющихся попыток используется проверка истории через .some вместо добавления еще и Set, чтобы не было лишней синхронизации с массивом истории.

### Алгоритм `evaluateGuess`

Основная функция для подсчета Bulls and Cows. На входе получаем секрет и саму попытку, далее разбиваем их на массив символов. Чтобы посчитать количество bulls нужно выбрать и посчитать сколько цифр у секрета стоят на том же месте, где и у попытки. Для подсчета cows нужно просто посчиать сколько всего цифр совпадает у секрета и у попытки, но нужно учесть при этом и bulls, ведь цифра находящаяся на своем месте это только bull и в зачет cow не идет.

### Алгоритм `countPossibleSecrets`

Рекурсивная функция для подсчета возможных варинатов при определенном length и base. Так как секретное слово состоит из уникальных цифр, то подсчет идет по формуле: A(k, n) = n * (n - 1) * (n - 2) * ... * (n - k + 1), где k - length, n - base. То есть для (bin, 2) A = 2 * 1 = 2, для (dec, 4) A = 10 * 9 * 8 * 7 = 5040, для (hex, 3) A = 16 * 15 * 14 = 3360

В самой функции два базовых случая:

- length === 0 => 1 - в случае когда мы дошли по base до 0, чтобы не умножить потом результат на 0
- length > base => 0 - если вдруг не хватило цифр для нужной длины по базе (хотя и проверяется в ui, но ведь чистый и функциональный код)

## 2. Сложность

- `generateSecret` - Тут сложность O(n * b), где B - это base, а n - length. Мы n раз рекурсивно вызываем функцию, и на каждом шаге пробегаемся по массиву длиной около b через filter, создавая его копию.
- `evaluateGuess` - Тут сложность O(n^2). Квадрат получается из-за строчки с подсчетом common. Мы запускаем filter по массиву guessChars (это n шагов), и на каждом шаге вызываем includes по массиву secretChars (это еще до n шагов внутри). Получается вложенный цикл: n умножаем на n и получаем O(n^2).
- `isValidGuess` - Тут сложность O(n + b) по времени и по памяти. Это несколько проходов один за другим.
- `countPossibleSecrets` - O(n) - до memoize, O(1) - после. В первый проход это n рекурсивных вызовов, после это уже Map с доступом по ключу O(1)

## 3. Принципы чистого кода

- Разделение ответственности - папки `core` и `ui` - в `core` логика игры, без document, window, localStorage; а в `ui` - все что рабоает с DOM
- Нет дублирования/повторения (DRY) - `createDigitValidator` используется и в `isValidGuess`, и в `app.ts` для фильтрации ввода
- Говорящие имена - например `getGuessRejection`, `isSameSettings`, `compareRecords`, `createInitialState` - по названию понятно, что делает функция
- Одна функция, одна задача - `addRecord`, `getTopRecords`, `createRecord` и `parseRecords` из `src/core/records.ts` делают по одной вещи, а не одну большую функцию.
